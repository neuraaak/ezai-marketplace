# AGENTS.md — ezai-marketplace

Instructions for AI coding agents (Codex, Claude Code, Gemini CLI, Copilot, etc.) working in this repository.

---

## Project overview

`ezai-marketplace` is a curated CLI for installing AI skills (Markdown files) into Claude Code, Gemini CLI, and GitHub Copilot. Skills are copied to `~/.agents/skills/<name>/` and symlinked into each platform's skills directory.

- **Package name:** `ezai-marketplace` — published on npm, used as `npx ezai-marketplace` or `ezai`
- **Node.js ≥ 22.13, pnpm ≥ 11** (see `engines` in `package.json`)
- **License:** MIT

```text
  commands/

    info.js                        ezai info <plugin>

  SKILL.md                         Skill content (always at plugin root)
  references/<lang>/*.md           Language-specific references (loaded on demand)
  references/common/*.md           Cross-cutting references
  evals/eval_set_*.json            Eval sets (skill_name must be prefixed ezai-)
.claude-plugin/marketplace.json    Central catalogue (regenerated by build-index)
scripts/build-index.js             Regenerates the catalogue (runs as pre-commit hook)
docs/                              VitePress documentation site
```

## Coding conventions

- **CommonJS only** — `require()` throughout, no ESM (`import`). Do not add `"type": "module"` to `package.json`.
- **No TypeScript** — plain `.js` files.
- **Language convention** — CLI messages and code comments are in French; documentation (`docs/`, `AGENTS.md`, plugin descriptions, `## Capabilities`) is in English. This split is intentional and must be preserved.
- **No comments** unless the _why_ is non-obvious. Never describe what the code does.
- **No magic numbers** — enforced by `herald.config.json`.
- **Max 500 lines per file** — enforced by `herald.config.json`.
- **Path safety** — all plugin paths go through `assertSafeRelPath()` before any `fs` call; never bypass this.
- **Error handling** — validate at system boundaries (user input, file system). Do not add defensive guards for states that cannot occur.

---

## Plugins

- All plugin names are **prefixed `ezai-`** (e.g., `ezai-docs-writer`, `ezai-cicd-expert`).
- `SKILL.md` lives at the **plugin root**, not inside a `skills/` subdirectory.
- `SKILL.md` must be a **thin router** — no content duplicated from reference files. Progressive disclosure via `references/index.md`.
- Reference files follow the **maximise common, minimise coupling** principle:
  - `references/common/` — language-agnostic content (principles, templates, anti-patterns)
  - `references/<lang>/` — only content that is intrinsically language-specific (docstring syntax, toolchain config, badge registries)
- Eval files in `evals/` must use `skill_name` prefixed with `ezai-`.
- **Do not commit** `plugins/` entries that are test fixtures or examples — use in-memory or temp-dir fixtures in Jest tests instead.

## CI / pre-commit

- **Husky** runs `build-index` and `lint-staged` before each commit.
- `lint-staged` formats `.js` with Prettier + ESLint, formats `.json/.md/.yml/.yaml` with Prettier.
- **GitHub Actions** (`.github/workflows/`): Node matrix 22/24, pnpm 11. The `prepare` script skips husky when `CI=true`.
- All 48 Jest tests must pass before opening a PR.

---

## What NOT to do

- Do not modify `.gitignore` to include `docs/superpowers/` — specs and plans are intentionally local-only.
- Do not edit the installed copy (`~/.claude/skills/<name>/`) directly; always edit `plugins/<name>/SKILL.md` first.
- Do not over-architect: the design is intentionally simple (Git repo + JSON catalogue + Node.js CLI).
- Do not add features, fallbacks, or abstractions beyond the scope of the current task.
