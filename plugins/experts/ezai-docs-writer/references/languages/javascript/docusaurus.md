# Docusaurus — Config, Navigation & Deployment

Load this file **instead of** the VitePress parts of `toolchain.md` and `plugins-deploy.md` when the site uses Docusaurus (`docusaurus.config.*`). JSDoc/TSDoc rules in `standards.md` still apply; the admonition syntax below replaces the VitePress one. Page structure comes from the site's profile (`profiles/<profile>/templates.md`).

---

## Layout & config

```txt
docusaurus.config.ts     ← site config (TypeScript and ESM are supported natively)
sidebars.ts              ← sidebar definition
docs/                    ← Markdown/MDX pages, one folder per section of the profile
src/pages/index.tsx      ← React landing page (optional)
static/                  ← copied as-is to the build output
```

Canonical fields for a project site on GitHub Pages — derive every value from the project:

```ts
// docusaurus.config.ts
import type { Config } from '@docusaurus/types';

const config: Config = {
  title: '<project>',
  url: 'https://<owner>.github.io',
  baseUrl: '/<project>/',
  organizationName: '<owner>',
  projectName: '<project>',
  trailingSlash: false,
  onBrokenLinks: 'throw',
  presets: [['classic', { docs: { sidebarPath: './sidebars.ts' } }]],
};

export default config;
```

## Navigation

Two surfaces, mirroring the navigation structure of the site's profile:

- **Navbar** — `themeConfig.navbar.items`, one entry per top-level section.
- **Sidebar** — `sidebars.ts`. Prefer the autogenerated form (`{ type: 'autogenerated', dirName: '.' }`) and order it from the files:
  - page order and label: front matter `sidebar_position` and `sidebar_label`;
  - folder label and order: a `_category_.json` (or `.yml`) in the folder, with `label` and `position`.

Hand-write the sidebar only when the order cannot follow the folder tree.

## Homepage & badges

The badges rule (`common/standards.md`) targets the docs landing page. Under Docusaurus it is:

- the doc served at the site root — the page with front matter `slug: /`, or the root of `docs/` in docs-only mode (`routeBasePath: '/'`);
- otherwise the first doc users land on (often `docs/intro.md`). Do not put badges in `src/pages/index.tsx`: it is React, not Markdown, and drifts from the README block.

Put the badges block right after the page's H1 (or right after the front matter when the title comes from `title:`).

## Admonitions

Semantics live in `common/standards.md`. Docusaurus syntax:

```markdown
:::tip[Performance]
Pin the package manager in CI to avoid lockfile drift.
:::
```

Types: `note`, `tip`, `info`, `warning`, `danger`. Map the universal types: `example` → a fenced code block, `abstract` → lead paragraph.

Docusaurus 3 parses `.md` and `.mdx` with MDX 3: a bare `{` or `<` in prose is read as JSX and breaks the build. Escape it (`\{`, `&lt;`) or put it in inline code.

## API reference (`docusaurus-plugin-typedoc`)

Generates the TypeDoc reference as Markdown into `docs/api` during `start` and `build`:

```ts
plugins: [
  ['docusaurus-plugin-typedoc', { entryPoints: ['../src/index.ts'], tsconfig: '../tsconfig.json' }],
],
```

Install `typedoc`, `typedoc-plugin-markdown` and `docusaurus-plugin-typedoc` as dev dependencies. Never hand-edit `docs/api`.

## Versioning

Built in. Snapshot the current docs at release time:

```bash
npm run docusaurus docs:version 1.2.0
```

This writes `versioned_docs/version-1.2.0/`, `versioned_sidebars/` and `versions.json` (newest first). Commit all three; edit `docs/` and re-snapshot rather than editing a versioned copy.

## Deployment (GitHub Pages)

`npm run build` emits the site into `build/`. Upload it with `actions/upload-pages-artifact` and deploy with `actions/deploy-pages`, with `pages: write` + `id-token: write` on the deploy job only. See the `ezai-cicd-expert` skill for the full workflow.

## Anti-patterns

| Anti-pattern                                     | Problem                                      | Fix                                                |
| :----------------------------------------------- | :------------------------------------------- | :------------------------------------------------- |
| `trailingSlash` left undefined on GitHub Pages   | Pages adds slashes; links and assets break   | Set `trailingSlash: true` or `false` explicitly    |
| `baseUrl` missing or mismatched                  | Every asset and link 404s under the subpath  | `baseUrl: '/<project>/'`, with trailing slash      |
| `onBrokenLinks: 'ignore'`                        | Broken links ship silently                   | Keep `'throw'` so the build fails on a broken link |
| Badges in `src/pages/index.tsx`                  | Out of sync with the README block            | Badges in the Markdown landing doc                 |
| Bare `{` or `<` in prose                         | MDX parse error at build                     | Escape it or use inline code                       |
| Hand-editing `versioned_docs/` or `docs/api`     | Diverges from source; overwritten on rebuild | Edit `docs/` or the source comments, then rebuild  |
| Hand-written sidebar duplicating the folder tree | Drifts as pages are added                    | Autogenerated sidebar + `sidebar_position`         |
