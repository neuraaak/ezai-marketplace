# Starlight (Astro) — Config, Navigation & Deployment

Load this file **instead of** the VitePress parts of `toolchain.md` and `plugins-deploy.md` when the site uses Starlight (`astro.config.*` importing `@astrojs/starlight`). JSDoc/TSDoc rules in `standards.md` still apply; the aside syntax below replaces the VitePress admonitions. Page structure comes from the site's profile (`profiles/<profile>/templates.md`).

---

## Layout & config

```txt
astro.config.mjs         ← Astro config with the Starlight integration
src/content.config.ts    ← content collection declaration (required)
src/content/docs/        ← Markdown/MDX pages; the folder tree becomes the URLs
public/                  ← copied as-is to the build output
```

```js
// astro.config.mjs
import { defineConfig } from 'astro/config';
import starlight from '@astrojs/starlight';

export default defineConfig({
  site: 'https://<owner>.github.io',
  base: '/<project>',
  integrations: [
    starlight({
      title: '<project>',
      sidebar: [{ label: 'Guides', items: [{ autogenerate: { directory: 'guides' } }] }],
    }),
  ],
});
```

```ts
// src/content.config.ts
import { defineCollection } from 'astro:content';
import { docsLoader } from '@astrojs/starlight/loaders';
import { docsSchema } from '@astrojs/starlight/schema';

export const collections = {
  docs: defineCollection({ loader: docsLoader(), schema: docsSchema() }),
};
```

## Navigation

The sidebar is the only navigation surface, configured in `starlight({ sidebar })`. Mirror the navigation structure of the site's profile with one group per section, each autogenerated from its folder (`autogenerate: { directory: '<folder>' }`). Order and label pages from their front matter: `sidebar: { order, label }`.

---

## Page titles & badges

Every page needs a `title` in its front matter, and Starlight renders it as the page's H1. **Never write a `#` heading in the body**: start with a paragraph, then H2 and below.

The badges rule (`common/standards.md`) targets `src/content/docs/index.mdx` (the site root): put the badges block first in the body, right after the front matter. A `template: splash` homepage with a `hero` keeps the badges just below the hero.

---

## Asides

Semantics live in `common/standards.md`. Starlight syntax:

```markdown
:::tip[Performance]
Pin the package manager in CI to avoid lockfile drift.
:::
```

Types: `note`, `tip`, `caution`, `danger`. Map the universal types: `warning` → `caution`, `info` → `note`, `example` → a fenced code block, `abstract` → lead paragraph.

---

## API reference (`starlight-typedoc`)

Generates the TypeDoc reference into the site and exposes a ready-made sidebar group:

```js
import starlightTypeDoc, { typeDocSidebarGroup } from 'starlight-typedoc';

starlight({
  plugins: [starlightTypeDoc({ entryPoints: ['../src/index.ts'], tsconfig: '../tsconfig.json' })],
  sidebar: [typeDocSidebarGroup],
});
```

Install `typedoc`, `typedoc-plugin-markdown` and `starlight-typedoc` as dev dependencies. Never hand-edit the generated pages.

## Versioning & i18n

- **Versioning** is not built in. Use the community `starlight-versions` plugin only when old versions must stay browsable; otherwise publish the latest docs only.
- **i18n** is built in — the reason to pick Starlight. Declare `locales` (and `defaultLocale`) in the `starlight()` config; each locale gets its own subfolder under `src/content/docs/`.

---

## Deployment (GitHub Pages)

`astro build` emits the site into `dist/`. Upload it with `actions/upload-pages-artifact` and deploy with `actions/deploy-pages`, with `pages: write` + `id-token: write` on the deploy job only. See the `ezai-cicd-expert` skill for the full workflow.

## Anti-patterns

| Anti-pattern                                 | Problem                                    | Fix                                               |
| :------------------------------------------- | :----------------------------------------- | :------------------------------------------------ |
| `#` heading in the page body                 | Two H1s; the title renders twice           | Title in front matter only; body starts at H2     |
| Missing `src/content.config.ts`              | Pages are not collected; the site is empty | Declare the `docs` collection with `docsLoader()` |
| `site` / `base` missing on GitHub Pages      | Assets and links 404 under the subpath     | Set `site` and `base: '/<project>'`               |
| `:::warning` aside                           | Not one of Starlight's aside types         | Use `:::caution`                                  |
| Hand-ordered sidebar duplicating the folders | Drifts as pages are added                  | `autogenerate` per folder + `sidebar.order`       |
| Hand-editing generated API pages             | Overwritten on the next build              | Fix the source comments, then rebuild             |
